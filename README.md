# Мидгард

Играбельная проверка браузерной survival-игры по [game-speck.md](game-speck.md). Соло, обычная сложность, три связанные земли (лес, снега и огонь), три роли обычных монстров и три босса. Графика — процедурная изометрия Canvas 2D, без загружаемых ассетов и внешних зависимостей.

## Запуск

Требуется Node.js 22 или новее. Установка пакетов не нужна.

```sh
npm run dev
```

Откройте `http://localhost:5173`. Сервер слушает все интерфейсы. При запуске на компьютере в одной Wi-Fi-сети с iPhone откройте на телефоне `http://<локальный-IP-компьютера>:5173`. Для удалённого рабочего окружения потребуется доступный пользователю preview / проброс порта; `localhost` телефона не указывает на удалённый сервер.

```sh
npm run check
npm test
npm run build
```

Сборка создаёт `dist/`. На статическом HTTP-хостинге, в том числе Netlify Drop, без отдельного сервера работает только соло. Для комнат нужен запущенный Node-сервер и маршрут `/api/*` к нему. Для локальной проверки сборки: `SERVE_DIR=dist PORT=5174 npm start`. Открытие `index.html` через `file://` не поддерживается из-за ES modules.

## Первая сессия

1. Двигайтесь левым сенсорным кругом или WASD. Подойдите к дереву, камню или ягодам. Дерево требует 4 удара, камень — 5; удерживайте кнопку действия / физическую клавишу E, чтобы продолжать добычу. Ягоды собираются одним действием. Ресурс подсвечивается и показывает прогресс, материалы выдаются после последнего удара. После истощения виден таймер восстановления. Русская раскладка поддерживается. На карте M видны дом, могилы и древний круг.
2. Соберите дерево, отметьте участок через «Строить». Выберите пол, зажмите палец / левую кнопку мыши и протяните область. Для стен выделите область готовых полов: стены соединятся по её периметру. Одиночное касание выбирает ближайшее внешнее ребро. R / кнопка ребра переключает автоматический выбор и 6 фиксированных сторон. Предпросмотр показывает область и стоимость; отпускание подтверждает всю постройку, отмена жеста ничего не тратит. Для двери разберите один сегмент стены и поставьте дверь на его место. «Готово» выходит из размещения.
3. Постройте очаг и верстак. У верстака создайте меч; после охоты будут доступны лук и броня. У очага готовьте мясо. Сумка показывает сетку предметов: выберите предмет для описания и использования. Кнопками 1–9 в описании назначьте его на пояс. В игре нажмите соответствующую цифру или ячейку пояса, чтобы взять оружие / съесть еду / выпить зелье. У очага из 2 ягод и 2 лечебных трав варится зелье здоровья: +40 HP, не выше максимума, повторное применение через 20 секунд активной игры. При полном здоровье оно не расходуется. Закрытое помещение с полом и очагом позволяет восстанавливать здоровье в покое, когда персонаж сыт и рядом нет монстров.
4. На пятой минуте начинается ночь, длительностью три минуты. Если есть оборудование дома, сначала появится 25-секундное предупреждение о набеге. От 28 единиц функциональной стоимости приходит разрушитель. Украшения и обычные стены не повышают угрозу.
5. В бою используйте направленный удар, удержание блока и перемещение. Контрудар удалён. У меча есть замах, активный взмах и восстановление; урон проверяется только во время прохода клинка рядом с противником. Лук расходует стрелы. Изучайте записи на камнях и хранителя в северо-восточной части карты. Его вторая фаза добавляет круговую атаку; после проигранной попытки здоровье восстанавливается полностью.
6. После смерти выберите старт или домашнюю лежанку. Вещи остаются на месте гибели без таймера удаления. Монстры не уничтожают складские запасы, но их близость блокирует использование оборудования.

В лесу стало меньше ресурсных узлов, но стартовые припасы сохранены. Появились три озера, скальные гряды, берега, пустоши и три скопления врагов. Вода и горы непроходимы; скалы также закрывают линию выстрела. Карта показывает препятствия и логова.

## Сохранение

Автоматически каждые 10 секунд активной игры, после основных действий, при паузе и уходе со страницы. Мир не продвигается в фоне или закрытом браузере. В меню паузы есть ручное сохранение и экспорт/импорт JSON-копии; импорт и новый мир требуют подтверждения. Аккаунта и синхронизации нет. Очистка данных браузера удаляет локальное сохранение.

## Проверка на iPhone 12 / Safari и Chrome

Браузерные и физические тесты в среде разработки не выполнялись: установленного браузера нет. Автоматические проверки Canvas/DOM используют тестовые адаптеры и не подтверждают внешний вид, FPS или удобство.

- Добыча: удержать действие у дерева и камня днём/ночью; отойти во время замаха, закрыть игру и вернуться. Проверить прогресс, отмену незавершённого удара и подсказку у пня.
- Интерфейс: съесть похлёбку, проверить уведомление над поясом, одновременно показать набег и режим строительства; открыть сумку, прокрутить её и закрыть крестиком. Проверить с открытыми/скрытыми панелями Safari.
- Игровая область: длительные свайпы по миру и стику, второй палец на блоке/ударе, отпускание пальцев в разном порядке. Страница не должна двигаться или пружинить, управление не должно залипать. Длинное меню крафта должно по-прежнему прокручиваться внутри панели.
- Горизонтальный экран: доступность кнопок большими пальцами, отсутствие перекрытия интерфейса вырезом и нижней полосой; движение одновременно с атакой и блоком.
- Строительство: протянуть пол 3×3, затем стены вокруг него; проверить стоимость, отмену жеста и отказ при недостатке материалов. Пройти вдоль всех стыков и углов, открыть/закрыть дверь, проверить укрытие. Второй палец на стике не должен перехватывать выделение.
- Сумка и пояс: выбрать предмет, назначить на 1 и 9, сменить оружие и выпить зелье с клавиатуры / касанием; проверить подписи, счётчики, перезарядку и сохранение назначений.
- Ландшафт: обойти озёра и скалы, найти проход к боссу, оценить опасность скоплений врагов.
- Анимации: бег и остановка героя, волка, скитальца, разрушителя и босса; замахи и удары, выстрел из лука, остановка анимаций на паузе. Проверить детализацию построек, открытые двери и руины при разном освещении.
- Бой: читаемость подготовки атак, совпадение взмаха меча с попаданием, возможность уйти от круговой атаки босса, различимость трёх противников.
- Свернуть и вернуть Chrome, заблокировать телефон, повернуть экран: нет скрытого расхода сытости и залипшего движения. Перезагрузить страницу и продолжить сохранение.
- Нападение на дом, когда персонаж далеко: предупреждение и счётчик; возвращение, освобождение сундука и ремонт. Смерть около занятого дома не лишает выбора стартовой точки.

Проверка реальной геометрии в браузере: после `npm run dev` откройте `/tools/layout-check.html` и нажмите «Проверить размеры экранов». Страница проверяет 54 сочетания размера, режима и безопасных отступов, ищет пересечения HUD, выход за экран, наложения кнопок и смещение крестика. Она использует изолированную копию интерфейса без чтения/изменения сохранений. В среде без браузера этот прогон не выполняется. Автотесты Node отдельно проверяют расчёт зон, добычу днём/ночью, русскую клавиатуру и удержание E через интерфейс.

Геометрия HUD сосредоточена в `src/layout.js` и `src/hud.css`: верхняя полоса, боковые статусы, центральные предупреждения и нижний блок управления. Уведомлению постоянно отведена отдельная строка над поясом. Высота пересчитывается при изменении visual viewport; на коротких экранах второстепенные подписи скрываются. Цвета и материалы остаются в `style.css`.

## Текущие ограничения

Это первая проверка механик, не законченная визуальная версия. Изображения рисуются геометрией, с процедурными анимациями бега и ударов, детализированными постройками и растительностью, без внешних текстурных ассетов; музыка и эффекты синтезируются через Web Audio. Крыша условная: замкнутый контур стен/дверей над полом считается укрытием, отдельного размещения крыши нет. Лес пока не включает погодную угрозу. Навигация монстров простая; сложные лабиринты из стен требуют ручной проверки. Числа рецептов, времени, урона и опыта — стартовый баланс, длительность прохождения и производительность iPhone не измерены.

На личной обороне части дома могут разрушаться полностью, в отсутствие игрока остаются ремонтируемые руины. Штраф навыков за смерть не добавлен; перенос опыта у верстака теряет 20%. Первая магия открывается через кристаллы снежной земли. Перенос дома, повышенная сложность и онлайн остаются в планах.

Логика находится в `src/game.js`, отрисовка в `src/render.js`, интерфейс и жизненный цикл страницы в `src/main.js`. Тесты используют встроенный Node test runner.

Управление использует Pointer Events с отдельным захватом указателя для каждого органа управления. HTML/body закреплены без прокрутки; `touch-action: none` и непассивный WebKit fallback ограничены игровыми поверхностями, а меню сохраняют собственную прокрутку. Viewport meta и масштаб Canvas не менялись. Системные жесты iOS, начинающиеся вне содержимого страницы (например, вызов домашнего экрана), не контролируются веб-игрой.

Мир и строительство используют гексагональную сетку с шестью соседями. Новые стены занимают рёбра, а не целую клетку. Герой и обычные монстры увеличены на 30%, босс существенно увеличен. Старые сохранения загружаются с сохранением ресурсов и построек: прежние стены без ориентации отображаются тонкими контурами прежних клеток; старый участок сохраняет свою границу. Для оценки новой планировки удобнее новый мир, но его создание не требуется.

Обновление ландшафта применяется и к старым сохранениям: инвентарь, склад, дом и прогресс сохраняются; ресурсные узлы обновляются, группы врагов и животные обновляются однократно. Старый участок остаётся ровной проходимой площадкой. Персонаж, враги и могилы, оказавшиеся внутри нового препятствия, переносятся на ближайшую сушу. Ключ локального сохранения сохранён для совместимости при переименовании игры.

## Расширенный лес

Суша примерно вдвое больше, с неровной круглой границей. Группы по 1–3 монстра патрулируют лес. Зайцы и олени убегают и дают мясо/шкуры. Папоротники дают лечебные травы, грибные группы — грибы для похлёбки; встречаются поваленные стволы, рунические камни и родники, ускоряющие восстановление энергии. Йотун корней использует взмах, круговой удар и дальний залп; ниже половины здоровья становится быстрее.

Музыка и эффекты запускаются после «Начать»/«Продолжить». Отключаются независимо в паузе, настройки сохраняются. Проверьте на телефоне громкость, повтор мелодии, паузу при сворачивании, подсказки атак босса и иконки состояний. Браузер и звуковой вывод в рабочем окружении отсутствуют: автоматические проверки подтверждают логику, но не визуальную читаемость и качество звучания.

## Путь через три земли

После лесного босса создайте меховой плащ у верстака и идите на восток в Йотунхейм. Добывайте кристаллы для руны мороза: назначьте её на пояс и используйте в бою (30 энергии, перерыв 4 секунды). Сердце Хрима позволяет создать огнестойкий плащ; южный переход ведёт в Муспельхейм. Обсидиан нужен для усиливающей урон печати. Сурт завершает сагу. Климатические плащи работают из инвентаря; без защиты мороз и жар начинают наносить урон после 12 секунд.

Музыка теперь имеет смену гармоний и партий, стерео и реверберацию; звуки комбинируют шум и резонансы. Проверьте вручную баланс фоновой музыки и ударов, переключение биомов и возобновление аудио после сворачивания. Проверьте виды спереди/со спины при вертикальном движении и отсутствие дрожания животных у границ бегства. Качество звучания и ощущение анимаций на iPhone ещё не оценены человеком.

Ландшафт отображается без видимых гексов: непрерывная текстура сглаживает переходы между поверхностями и кэшируется небольшими участками. Сетка появляется при строительстве. Горы различаются силуэтами, уступами, породой, осыпями и снегом. При ручной проверке осмотрите берега и тропы в движении, стыки текстуры, обзор героя за скалами и строительную сетку на iPhone. Физические границы воды и гор не изменены.

Последнее обновление: название — «Мидгард», без подзаголовка. Камера и объекты приближены на 40%; доработаны руки героя и мелкие детали. Снос возвращает все материалы рецепта. Иконки стали цветными предметными миниатюрами. У земель самостоятельные инструментальные темы с лирой, смычковыми, флейтой, рогом и барабаном. Подготовка сэмплов проходит в фоновом потоке; в первые секунды музыка может ещё не звучать.

После запуска dev-сервера откройте [/tools/presentation-preview.html](/tools/presentation-preview.html), чтобы прослушать три композиции без путешествий по миру и рассмотреть все иконки. Страница не работает с сохранениями игры. Проверьте музыку в наушниках и на динамике iPhone, переходы между темами, видимость рук и точность строительства при приближённой камере.

Текущее обновление аудио и экипировки: три 36-тактовые композиции с двумя мелодическими темами, девятью инструментальными тембрами и сменой плотности ансамбля. В паузе — отдельные сохраняемые уровни музыки и эффектов (0–100%). Герой начинает в холщовой одежде; броню и новый деревянный щит можно надевать/снимать через сумку и пояс. Щит создаётся у верстака: 8 дерева, 2 шкуры, 1 смола. Блок руками поглощает 20% урона, щитом — 80% при начальном навыке; с луком используется блок руками. Руки упрощены до двух сегментов постоянной длины. Вручную проверьте хват меча/топора, бег, блок со щитом и без него, вид брони при переключении, полные музыкальные фразы и баланс каналов на iPhone. Синтез не заменяет записи живых инструментов; качество на слух здесь не проверено.

Уточнение внешнего вида: руки короче и сгибаются наружу, топор удерживается одной рукой, видимый плащ убран. Климатические предметы сохранены. Подсказки: наведение мышью/фокус или «?» → нажатие на элемент на телефоне; режим ставит игру на паузу и не расходует предметы. Выход — «×»/Escape. Проверьте вручную руки во всех направлениях и подсказки поверх открытой сумки на iPhone.

## Совместная игра и запуск сервера

«Играть с друзьями» → настройка героя → «Создать комнату». Передайте код другу; на том же адресе игры он нажимает «Войти по коду». Максимум четыре героя; общий дом и отдельные вещи. PvP включается каждым в меню паузы и действует только взаимно. Меню не останавливает сетевой мир. При потере связи герой может получать урон ещё 30 секунд; через 0,8 секунды его движение останавливается. Повторный вход с того же браузера восстанавливает героя.

Новые зависимости не нужны. Node 22+: `npm run build`, затем `SERVE_DIR=dist PORT=5173 DATA_DIR=/постоянный/диск/midgard npm start`. Для интернета направьте HTTPS-домен через reverse proxy на этот Node-процесс, сохраняя Host и пропуская `/api/*`; это обычные JSON POST-запросы. Процесс должен постоянно работать. Только статического хостинга недостаточно. Конкретный хостинг и публичный адрес пока не подключены.

Сервер сохраняет комнаты каждые 10 секунд в `DATA_DIR/rooms.json` (по умолчанию `.midgard-data/`). Последние 10 секунд могут потеряться при аварийном завершении. Каталог содержит секреты восстановления героев: храните его вне публичного web-root и делайте резервную копию. Встроенный сервер раздаёт только публичные index/style/src/tools; каталог данных не раздаётся. Секрет героя хранится локально в браузере, не включается в снимки мира для друзей. Ограничение текущего сервера — 50 сохранённых комнат; это версия для небольшой компании, не массовый публичный сервис.

Новая прогрессия: ледяные шкуры и кристаллы → ледяное снаряжение; угольные сердца и обсидиан → огненное. Холод/жар без защиты: 6/9 HP в секунду после 6 секунд предупреждения. Хрим создаёт ледяную волну с безопасным внутренним кольцом и последующей уязвимостью; Сурт отмечает метеоры и призывает помощников. Внешность монстров, боссов, деревьев и минералов различается между землями.

Ручная проверка: два разных браузера/телефона в одной комнате, движение и сбор одним игроком на экране другого, стройка, смерть/возврат, переподключение, оба состояния PvP, внешний вид героя, телеграфы боссов. HTTP и игровые тесты не заменяют оценку задержки, кадров и удобства на реальном iPhone.

## Рекомендуемый запуск на Render

В репозитории есть **render.yaml**. Он поднимает один Web Service, который обслуживает игру и комнаты по одному HTTPS-адресу. Netlify для этого не нужен.

1. Загрузите актуальный коммит в свой Git-репозиторий.
2. В Render выберите **New → Blueprint**, подключите репозиторий и ветку с этим коммитом. Render прочитает render.yaml.
3. Проверьте ресурсы перед подтверждением: тариф **starter** и постоянный диск **1 GB** платные. Они выбраны, чтобы комнаты сохранялись после перезапусков. Бесплатный сервис без постоянного диска не обеспечивает сохранность комнат.
4. После успешного запуска откройте выданный сервису адрес onrender.com и передайте именно его друзьям. «Играть с друзьями» → создать комнату → передать код.

При ручном создании Web Service: Runtime — Node; Build Command — `npm run build`; Start Command — `npm start`; Health Check Path — `/healthz`. Переменные: `NODE_VERSION=22`, `NODE_ENV=production`, `SERVE_DIR=dist`, `DATA_DIR=/var/data/midgard`. Подключите постоянный диск с Mount Path `/var/data`, размером 1 GB. PORT задаёт Render автоматически. Оставьте один экземпляр сервиса: комнаты этой версии хранятся в памяти одного процесса и на его диске.

`ROOM_SERVER_URL` и `ROOM_ALLOWED_ORIGINS` для игры непосредственно на Render не нужны. Не переносите туда примерные адреса из инструкции Netlify. Если вы всё же оставляете сайт на Netlify, используйте следующую инструкцию с реальными адресами.

Сервер проверяет доступность записи на диск при старте; `/healthz` возвращает JSON со status: ok. Комнаты сохраняются каждые 10 секунд и при SIGTERM/SIGINT, в том числе перед штатным перезапуском Render. Аварийная остановка всё ещё может потерять последние секунды — храните резервные копии диска. Реальное развёртывание на Render из этой среды не выполнялось.

После публикации проверьте: открытие сайта, создание комнаты и вход друга, переподключение к прежнему герою после ручного Restart сервиса.

## Netlify Drop: подключение комнат

Ошибка `Unexpected token '<' … is not valid JSON` означала, что `/api/create` вернул HTML сайта/ошибки Netlify вместо JSON сервера комнат. Клиент теперь различает этот случай, недоступность сервера и ошибки комнаты. Обновление файлов исправляет сообщение, но не запускает отсутствующий сервер.

Можно оставить сайт на Netlify Drop:

1. Разместите этот репозиторий на хостинге с постоянно работающим Node 22+ и постоянным диском. Запуск: `ROOM_ALLOWED_ORIGINS=https://ИМЯ-САЙТА.netlify.app DATA_DIR=/постоянный/диск/midgard npm start`. Сервис должен получить собственный HTTPS-адрес. Без `ROOM_ALLOWED_ORIGINS` разрешены только запросы с собственного сайта сервера.
2. Соберите сайт командой `ROOM_SERVER_URL=https://АДРЕС-СЕРВЕРА npm run build`. Указывайте адрес без пути `/api`, параметров и логина. Сборка создаст `dist/_redirects`, направляющий `/api/*` на сервер.
3. Загрузите **содержимое всей папки dist, включая _redirects**, в тот же сайт Netlify Drop. Оба друга должны открыть обновлённый сайт. Сборка без `ROOM_SERVER_URL` удаляет устаревшее перенаправление, чтобы случайно не оставить чужой сервер.

Адреса выше — шаблоны, их нужно заменить реальными. Репозиторий и папку данных сервера в Drop загружать не нужно. Альтернатива — открыть игру непосредственно по HTTPS-адресу Node-сервера: он раздаёт игру и комнаты вместе, без Netlify-прокси. Публикация Netlify Functions не заменяет постоянно работающую симуляцию этой версии.

Регенерация здоровья: 0,08 HP/с базово, до +0,72 HP/с от сытости, ещё +0,15/+0,30 HP/с от активного бонуса жаркого/похлёбки. Скорость видна в подсказке статуса регенерации при неполном здоровье. На телефоне проверьте читаемость статуса и темп восстановления в бою; баланс ещё нужно оценить вручную.
